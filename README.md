# Hymnes et Cantiques App

This is a mobile application developed in React Native and Expo for viewing the songs from the "Hymnes et Cantiques" Kinyarwanda version. The app allows users to navigate through a list of songs and view song details.

## Features

1. **Song List Screen**: Displays a list of all the songs. Users can search songs by title or song number.
2. **Song Detail Screen**: Displays the details of a selected song. The song number, title, subtitle, and verses are shown. Users can swipe left or right to navigate to the previous or next song.

## Data

The songs are stored in a JSON file, songs.json, which was generated by a Python parser from a .txt file containing the lyrics. The format of the data in the JSON file is as follows:
```json
[
    {
        "song_number": 1,
        "title": "TURAGUSINGIZA DATA",
        "sub_title": "N'icyubahiro",
        "verses": [
            "\n1. Turagusingiza Data,...",
            "2. Watuviriye nk'umucyo,..."
        ]
    },
    ...
]
```

## Setup and Installation

To set up the application on your local machine, follow these steps:

1. Clone the repository to your machine.
2. Run `npm install` to install all the dependencies.
3. Install the Expo CLI if you haven't already, by running `npm install -g expo-cli`.
4. Run `expo start` to start the Expo packager.
5. Open the app on your phone using the Expo client app.

## Web Audio From S3 (Offline Cache)
- Web can load melody MP3s from S3/CloudFront instead of bundling them in Firebase hosting.
- Default web audio base URL is `https://ntezi-media.s3.amazonaws.com/hymnes-cantiques/audio`.
- You can override it with `EXPO_PUBLIC_WEB_AUDIO_S3_BASE_URL` (see `.env.example`).
- File naming expected in S3: `hec_001.mp3` ... `hec_271.mp3` and `hec_200bis.mp3`.
- On web, songs are preloaded into browser cache when a song page is opened, then played from cache for offline replay.
- Configure S3/CloudFront CORS to allow `GET` from your web domain so browser preloading can fetch and cache the files.
- Android/iOS keep using bundled local audio.

### Audio Integrity Check (Local vs S3)
- Run: `npm run check:audio-s3`
- Defaults:
  - bucket: `ntezi-media`
  - prefix: `hymnes-cantiques/audio`
  - local dir: `./audio`
- Override defaults with args:
  - `npm run check:audio-s3 -- --bucket <bucket> --prefix <prefix> --dir <local-audio-dir>`
- Or set env vars:
  - `AUDIO_S3_BUCKET`
  - `AUDIO_S3_PREFIX`

The script reports:
- files missing in S3
- files extra in S3
- files with size mismatch
